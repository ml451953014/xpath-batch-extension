# XPath 批量文字提取

一个纯前端、完全本地运行的 Chrome / Chromium Manifest V3 扩展。选择列表中两个条目的同一字段，扩展根据 DOM 结构推导 XPath，并提供批量文字预览与导出。

不调用大模型，不需要服务端，也不把页面内容发到外部。

## 1.2.1 手动字段 XPath

- 当前字段 XPath 和「应用字段规则」常显，不再需要展开高级设置
- 已有记录范围时，直接输入行内相对 XPath 或完整页面 XPath 即可配置新列，无需再次采样
- 完整页面 XPath 只在页面上求值一次，再按元素/属性/文本节点所属记录归位；缺值留空，多命中提示歧义，记录范围之外的命中明确拒绝
- 记录范围仍必须返回元素，属性链接属于字段值；首次使用可两点采样建立范围，或在高级设置手填元素范围

## 1.2.0 交互重做

- 首列选两个样本后立即显示结果，记录行在后台自动识别，不再需要「确认记录集合」
- 五个主要操作：添加字段并拾取、删除当前字段、开始当前列拾取、复制表格、导出表格 CSV
- 新增、切换、取消或失败的采样不会清掉已完成列；已完成字段持续高亮，当前列用蓝色强调
- 未完成字段不参与复制/CSV，界面会明确显示跳过数量；已有列保持可导出
- 正在编辑的 XPath 属于草稿，只有成功应用才替换原规则；失败保留旧值，不会连带清空其他字段
- 记录范围、手动刷新等在默认收起的「高级设置」；1.2.1 已将字段 XPath 单独移出常显。实际页面数据变化仍需刷新后导出

## 1.1.1 修复

- 修复论坛“一个帖子一个 tbody”的布局被误判为不同列表，导致首列采样失败、无法确认记录集合的问题
- 对同一 table 中的多个 tbody，按各自的 tr 生成独立记录行；不会把一个含多行的 tbody 合并成一条记录
- 不同 table、表头与正文混选、不同嵌套表格仍需重新选择，推断的具体错误现在也会直接显示在面板顶部
- 新增 `fixtures/forum.html`，用合成的 63 个 tbody 复现此次结构并验证标题、作者、查看数对齐

## 1.1.0 更新

- 支持 XPath 元素、属性和文本节点集，例如 `/@href`、`/@src`、`/@id`、`/@class`、`/text()`；属性保持网页中的原始值，不自动补全 URL
- 新增多字段表格：先确认共同记录行，再为标题、作者、查看数量等字段分别采样；无命中的字段保留空单元格，多匹配显示歧义并阻止导出，不按各列命中序号拼接
- 滚动或无关轮播/懒加载变化不再直接清除批量高亮。按当前视口坐标重绘，并裁剪到嵌套滚动容器可见范围
- 页面变化合并后核对 XPath 命中集合、顺序、可见性和文字；真正的内容或虚拟列表变化仍要求重新评估，复制/导出前也再次核对
- 新增「预览显示序号」复选框，默认关闭。切换、重新评估或重选时保持当前勾选状态，关闭面板重新打开恢复默认；只影响预览，复制文本始终不含预览序号；单字段 CSV 仍有序号列，多字段 CSV 仅使用已配置的字段列

## 安装

1. 在 Windows 文件资源管理器中右键安装包，选择「全部解压缩」。不能直接加载或拖入 ZIP。安装包解压后的根目录包含 `manifest.json`；源码包的扩展文件位于 `extension` 文件夹。
2. 在 Chrome 打开 `chrome://extensions`；Edge 对应 `edge://extensions`。
3. 打开右上角的「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择包含 `manifest.json` 的文件夹（安装包解压根目录，或源码包中的 `extension` 文件夹）。
5. 打开一个普通网页，点击浏览器工具栏中的「XPath 批量文字提取」图标。可以先把扩展固定到工具栏。

扩展不需要构建或安装 Node.js。`node_modules`、测试文件和开发依赖都不是运行所必需的。

从旧版更新：把 1.2.1 安装包中的文件覆盖到原来加载的扩展文件夹，再在扩展管理页点击该扩展的「重新加载」，刷新目标网页并重新打开面板。标题显示 1.2.1。若另选新目录加载，应停用旧版本，避免同时运行两个同名扩展。

## 使用

1. 打开已经显示目标列表的网页，点击扩展图标打开浮动面板。
2. 点击「开始拾取」，在页面中点击一个目标字段，例如第一条结果的标题。
3. 直接点击另一个条目的同一字段，例如第三条结果的标题。选择时尽量点击文字所在的相同层级元素；按 Esc 可退出拾取，「重选 / 清除」可重新开始。
4. 查看生成的候选 XPath、命中数量和提取预览。优先检查「结构约束」候选；它会利用共同类名等结构信息缩小范围。
5. 如果需要，可修改 XPath 后点击「重新评估」。确认所有预览结果确实属于目标字段，再点击「复制所有文本」或「导出 CSV」。另有「复制 XPath」按钮。
6. 使用结束后关闭面板。刷新或导航后需要重新打开和采样。

如果两个样本属于不同字段、不同模块或 DOM 层级不同，扩展会给出警告，可能无法生成可靠候选。请重选样本，或手动填写 XPath。

### 多字段表格：按列添加即可

1. 切换到「多字段表格」，点击「添加字段并拾取」或「开始当前列拾取」，在两条不同记录上点击同一字段，例如两条音色名或两篇帖子的标题
2. 第二个样本选好后自动显示第一列结果，无需确认记录集合。可直接修改当前字段名称
3. 点击「添加字段并拾取」，再在两条记录中选择作者、语言或查看数。添加时前面完成的列、数值和高亮都会保留
4. 要重选某一列，先在字段列表选中它，再点「开始当前列拾取」。按 Esc 或再次点该按钮退出；选错、取消或推断失败时原规则和结果仍保留，成功后才替换这一列
5. 「删除当前字段」只删除选中的列；删除第一列不会删除其余列或打乱记录行
6. 随时可以「复制表格」或「导出表格 CSV」。只输出已完成的列，尚未配置的空列不会阻止其他列导出；界面会提示有多少未完成列被跳过

表格仍按同一 DOM 记录对齐：作者规则没有命中的记录保留空单元格，不会从下一行借作者。新规则产生多命中歧义时不会覆盖已经完成的规则；请收窄后重新应用。实际页面内容变化后，旧快照会标记过期并停止导出，展开高级设置刷新数据后再核对。

### 手动输入字段 XPath 与 href

选中要修改的列，在常显的「当前字段 XPath」框输入，点击「应用字段规则」。只更新当前列，失败保留原规则与其他列。

以截图中的卡片结构为例：`//*[@id="dd-grid"]/a` 是卡片记录范围，每条记录本身就是链接元素。因此链接列填写 `./@href`，不是 `./a/@href`。也可以直接填写完整页面路径 `//*[@id="dd-grid"]/a/@href`。两者按记录归属对齐，缺 href 的卡片保留空格。

- 相对 XPath 以 `.` 开始，例如 `./@href`、`./img/@src`、`./@id`、`./@class`、`./div/text()`
- 页面 XPath 以 `/` 或 `//` 开始，例如 `//*[@id="dd-grid"]/a/@href`；固定的 `a[1]/@href` 只填第一条对应记录，其余行留空，不复制第一值到所有行
- 新增列会自动进入拾取；直接输入 XPath 就会停止拾取，随后应用即可，不必真的点击样本
- 如果尚未建立记录范围，先在两条卡片选同一字段；也可展开高级设置，填返回元素的记录范围并应用，再填字段 XPath。不要把带 `/@href` 的属性路径当成记录范围
- 页面 XPath 只要包含范围外节点就会拒绝；请收窄到当前记录集。未匹配任何节点时整列缺值，应核对表达式

### 高级设置（可选）

- 需要属性值时，在常显的「当前字段 XPath」中填写或追加 `./a/@href`、`./img/@src`、`./@id`、`./@class`、`./a/text()`，点击「应用字段规则」
- 输入框只是草稿。修改但未应用时，预览、复制和导出仍使用原已完成规则；出错不会清空原字段
- 记录行范围通常自动识别。只有需要手工调整时才改「记录行 XPath」并点击「应用记录范围」；应用成功会重新提取全部已完成字段，请核对结果
- 「刷新数据」在页面实际内容变化后重新提取；序号选项只影响预览，不增加复制/多字段 CSV 的列
- 无共同类名的位置规则含同标签数量守卫，防止缺少前面字段后的错位。同样结构/数量但业务含义改变仍无法自动判断；请核对预览

字段必须来自同一记录集合，不能把另一块列表的作者或查看数按序号拼接。记录容器不能互相嵌套；相对字段 XPath 不能越出对应记录，页面字段 XPath 的全部命中也必须归属于当前记录集。两点采样不理解业务语义。

### 为什么不是把 `div[3]` 改成 `div[*]`？

XPath 中 `div[*]` 表示「存在子元素的 div」，并不表示「任意序号的 div」。要取消某一步的位置约束，应移除该步的 `[3]`，保留 `div`。

例如两个标题路径为：

```xpath
/html[1]/body[1]/main[1]/div[1]/a[1]
/html[1]/body[1]/main[1]/div[3]/a[1]
```

位置泛化后可以是：

```xpath
/html[1]/body[1]/main[1]/div/a[1]
```

但如果列表中插入广告，或某条记录缺少标题，单纯按位置可能误取。扩展也会尝试使用重复容器和字段的共同类名生成结构候选；候选不保证互为严格子集，界面显示实际命中项数。类名按完整 token 匹配，避免把 `item-ad` 当成 `item`。

### 候选含义

- 结构约束：从两个样本的共同祖先定位重复兄弟容器，再组合共同类名和字段相对路径；它是启发式推荐，不保证理解业务语义
- 同层位置泛化：移除重复容器的序号，保留一致的字段位置；适合结构整齐的列表，但更可能匹配广告或错位字段
- 仅两个样本：保守回退，只选中已点击的两个元素，不能当成整页批量提取成功

两个样本无法证明整页字段语义一致，导出前应核对完整预览。

## 支持范围与边界

- 只处理当前页面主文档中已经加载到 DOM 的普通元素及其属性/文本节点，不自动翻页、点击「加载更多」或滚动抓取
- 不穿透 iframe 和 Shadow DOM；canvas、图片里的文字和浏览器内置 PDF 预览不属于本版提取范围
- `chrome://`、`edge://`、浏览器扩展商店及其他受限制页面通常禁止注入；扩展图标显示 `!` 时请切换到普通网页
- 本地 `file://` 页面需要在扩展详情中开启「允许访问文件网址」后，浏览器才可能允许使用；不想开启可使用本地 HTTP 测试页
- 动态列表或虚拟滚动列表可能只把屏幕附近的记录放进 DOM，提取数量不能代表全部数据
- 页面变化以 120ms 窗口合并检查；只有当前 XPath 命中元素、顺序、可见性或提取文字发生变化时，才提示重新评估并禁用复制/导出。无关动画或几何变化只重绘高亮。导出前再次同步核对，避免合并检查窗口内输出过时结果；真实动态列表仍需重新评估或重选
- 隐藏元素和隐藏子节点会按 CSS / `hidden` / `aria-hidden` 等信息保守过滤；这不是逐像素视觉检测，遮挡、裁剪、屏外位置等情况未必能准确判断；高亮支持普通滚动和轴向缩放，旋转/倾斜/复杂变形的裁剪形状不保证逐像素一致
- 提取的是普通可见文本，会合并连续空白；不保留富文本、网页原排版、链接地址、CSS 伪元素文字或输入框的实时 value
- 手动 XPath 支持元素、属性和文本（含 CDATA）节点集；`/@href`、`/@src`、`/@id`、`/@class`、`/text()` 均可。`string()`、`count()`、`boolean()` 等顶层标量表达式不属于批量节点集，本版会明确报错，不会静默过滤
- 属性返回原始 `Attr.value`，例如网页写 `/post/123` 就导出 `/post/123`，不转换为绝对 URL；不会访问或自动打开 href/src。文本节点返回原始 `nodeValue`，而元素会提取归一化的可见文字
- 单字段模式遵循 XPath 标准：缺少属性就没有该属性节点，不自动插入占位行。需要保留每条记录与空值的对应关系时，请使用多字段表格
- 多字段的相对 XPath 如 `./a/@href`、`./img/@src`、`./@id`、`./a/text()`。每个单元格多于一个节点时视为歧义，包含多个文本片段的 `/text()` 也可能产生歧义；请收窄规则，不会自动拼接或取第一个
- 极大页面、复杂 XPath 或大规模命中会增加页面开销，应优先缩小查询范围；文字完整导出，但匹配高亮最多显示前 1000 个元素
- 不绕过登录、网站访问限制或反爬措施。请仅处理你有权访问和使用的数据

## 数据与安全

- Manifest 只申请 `activeTab` 和 `scripting` 权限，在你点击图标后向当前页面注入代码
- 不申请全站主机权限、Cookie、历史记录、持久化存储或后台网络权限
- 无遥测、无外部 API、无远程脚本；提取逻辑在浏览器本地执行
- 页面文本可能包含个人或业务敏感内容。复制、下载或进一步分享时，请自行确认接收方和用途
- 预览以文本形式显示内容，不把网页文字作为 HTML 执行
- 默认仅导出可见节点，属性/文本按其所属元素判断。取消可见过滤后，元素文本仍忽略隐藏后代，但显式属性/文本节点可以返回隐藏内容的原始值，请注意可能包含页面中未显示的数据
- CSV 使用 UTF-8 BOM、标准双引号转义，并对以 `= + - @` 开头（含前导空白）的潜在公式加前导单引号，降低电子表格公式注入风险；仍建议只打开可信数据
- 刷新页面后需重新采样。浏览器下载的文件和用户主动复制的剪贴板内容不会随关闭面板而清除

### 浏览器冒烟清单

- 安装后在普通网页打开、关闭、再次打开面板，不出现重复面板
- 连续选择两条记录的同一字段，确认不会触发原链接跳转
- 查看普通列表、广告混排、缺字段和嵌套列表的所有预览结果
- 编辑一个有效 XPath，再输入无效 XPath，错误应可见且面板仍可操作
- 验证隐藏元素过滤、文本复制、CSV 下载及中文显示
- 多字段第一列两点采样后自动出现表格；新增第二列时旧值与高亮保留，取消、失败及切换列不清空数据
- 添加未完成列后复制/CSV仍只包含已完成列；删除首列保留其余列，删除最后一列可重新开始
- 页面真实文字或行顺序变化时旧导出禁用，展开高级设置刷新数据后核对结果
- 中途取消选取、重复点击扩展图标、关闭面板和刷新页面后，页面交互正常
- 在受限制页面确认没有注入，图标 `!` 提示能在普通网页成功打开后清除

## 核心接口

| 接口 | 作用 |
| --- | --- |
| `absoluteXPath(element)` | 返回主文档元素的绝对 XPath |
| `evaluateXPath(document, xpath)` | 内部结构推断接口，仅返回元素数组 |
| `evaluateValueXPath(document, xpath, context?)` | 用户值提取接口，返回元素/属性/文本节点数组；无效或标量抛错 |
| `ownerElement(node)` / `isValueVisible(node)` / `extractValue(node)` | 节点所属元素、可见性和原始值/元素可见文字 |
| `inferCandidates(first, second)` | 返回 `{ candidates, warnings }`；每个候选含 `label`、`xpath`、`kind`、`warnings` |
| `xpathLiteral(text)` | 安全生成 XPath 1.0 字符串字面量，支持单双引号混合 |
| `isVisible(element)` | 对元素及祖先做保守可见性检查 |
| `extractText(element)` | 提取并归一化可见普通文本 |
| `toCSV(texts)` | 生成带序号和文本列的安全转义 CSV 字符串 |
